# 📚 纯净阅读 — 无广告小说阅读器

一个可在国行 iPhone 上使用的纯净小说阅读器，基于 **PWA** 技术，无需 Mac、无需开发者账号、无需上架审核。

---

## 功能

| 功能 | 说明 |
|------|------|
| 📄 TXT | 自动识别章节（第X章 / Chapter N / 卷集篇部），无章节标记时按字数自动分块；**自动识别编码**（UTF-8 / GBK / GB18030 / Big5 / UTF-16） |
| 📘 EPUB | 解析 spine 结构，按章节读取正文 |
| 📕 PDF | pdf.js 渲染，支持缩放、高清屏适配 |
| 📝 DOCX | mammoth.js 转换为可读文本并分章 |
| 📦 ZIP | 压缩包上传后自动解压，批量导入其中的小说 |
| 📚 书架 | 数百本书，网格自适应列数，卡片带**阅读进度条**（未读 / 已读 NN% / 已读完三态） |
| 🔀 排序 | 最近阅读 / 书名（中文拼音、数字感知）/ 导入时间 / 阅读进度，可持久化，**收藏始终优先** |
| 🏷️ 分类 | 自定义分类，可新增/移动 |
| ⭐ 收藏 | 收藏优先排序 |
| 🔍 搜索 | 按书名、作者实时过滤 |
| 🔖 书签 | 添加书签、跨书查看列表、点击跳回原位置；有书签时按钮显示小红点 |
| 📑 目录 | 由解析器**自动识别章节**生成列表，当前章高亮、可一键倒序；同弹窗另有「书摘」页签 |
| 🧰 底部工具栏 | 上一章 ｜ **可拖动的章节进度条** ｜ 下一章，再加 目录 / 白天夜间 / 阅读设置 三个快捷键 |
| 🚪 点外部关闭 | 阅读设置、目录、导入面板都支持点击弹窗外部区域关闭 |
| 🔤 阅读设置 | 字号、行间距实时调节 |
| 📄 翻页动画 | **覆盖（默认）** / 平移 / 仿真 / 无 四档，可切换并记忆。**覆盖**=只有当前页动、相邻页原地不动地露出来（最接近翻真书）；**平移**=整条横向带一起移动；**仿真**=绕书脊翻走带阴影。默认值由 `DEFAULT_ANIM` 单点定义，与设置面板初始高亮保持一致 |
| 📄 跟手拖动 | 拖过页宽 22% 翻页，否则弹回；支持快速轻甩；拖回来再松手不误判；到头有阻尼；纵向手势不误触。**四档动画都支持**（覆盖模式下底层先就位并静止，只有克隆的当前页跟手移动） |
| 📄 上下栏 | **浮层**（浮在文字上方，显示/隐藏不改变正文区域大小）· **紧凑**：顶部只有返回箭头 `‹` + 书签 + 菜单（无书名），底部两行 · **翻页即收起**，点屏幕中间调出；开书 3 秒后自动让开。高度集中在 `reader.css` 顶部的 `:root` 变量里 |
| 🎞️ 翻页动画 | 滑动 / 仿真（3D 翻页 + 阴影扫过）/ 无动画，可切换并持久化 |
| 🎨 主题 | 暖黄 / 纯白 / 夜间 / 护眼绿 |
| 💾 进度保存 | 自动保存章节与进度，切换页面/锁屏均触发 |
| 📴 离线可用 | Service Worker 全量预缓存，无外网依赖 |

## 技术特点

- 🎨 **统一矢量图标**：全部图标集中在 `js/icons.js`（24×24 描边、`currentColor`、圆头圆角）。
  原来界面用的是 emoji（📚🔖📥⭐📖📄📦📂🗑⚠📘📕📝），由各机型自己的字体渲染，
  形状/粗细/配色都不一致；现在换成一整套统一图标，颜色跟随主题自动变。
  尺寸用 `em` 跟随所在元素的 `font-size`，不逐个写死像素。
- 🖼️ **App 图标程序化生成**：`tools/make-icons.py` 用应用自身的配色画出
  「摊开的书 + 金色书签带」，改配色后重跑一次即可，不用再找图。
- 👆 **长按菜单贴近卡片**：长按约 380ms 弹出操作菜单，菜单**贴在卡片正下方**
  （放不下翻到上方、自动夹在屏幕内，带指向卡片的小箭头）。
  四项：**收藏 / 重命名 / 移动到分类 / 删除**。
  移动超过 10px 视为滚动、不触发；弹过菜单后抬手不会误打开书。
  时长与位移阈值集中在 `LONG_PRESS_MS` / `LONG_PRESS_MOVE_PX` 两个常量里。
  关闭逻辑用 `inMenuAction()` 排除"点在菜单项上"——否则 `touchstart` 会先于 `click`
  把菜单删掉，菜单项永远点不到。
  菜单项的 `data-i` 由 `actions.map` 的下标生成、点击时反查同一下标，
  所以增删菜单项**不需要手改任何硬编码下标**。
- ✎ **重命名只写一个字段**：`updateBookField(id, 'title', ...)`，**绝不 `saveBook`**
  （后者会把整本书连同几 MB 的 `fileData` 重写一遍，是历史卡顿与"打开第二本书失败"的根源）。
  输入框预填当前书名；取消 / 空 / 纯空格一律不改动
  （`'   '` 在 JS 里是真值，必须先 `trim()` 再判断——「移动到分类」曾经因为漏了这一步而造出空分类）。
- 🔁 **跨章滑动翻页**：手势的"还能不能翻"判定用 `neighbourExists(dir)`，
  把**相邻章节**也算进来（只判本章页码会让章首往回滑被判成"到头"而弹回）。
  覆盖模式下章界不再作废整段手势，退化为"松手判定"。

- **纯前端**：只用 HTML / CSS / JS，无构建工具、无后端、无数据库服务器
- **本地自托管**：所有第三方库都在 `lib/` 目录，不依赖任何 CDN（国内网络友好）
- **数据存本地**：书籍、进度、书签全部存在浏览器 IndexedDB 中，不上传任何服务器
- **无广告、无追踪**：没有任何统计脚本或广告代码

## 本地测试

双击 `start-server.bat`（**推荐**），或手动执行：

```powershell
cd novel-reader
python serve.py 8080
```

`serve.py` 会给每个响应加上 `Cache-Control: no-store`，所以**手机每次打开拿到的都是最新代码**。
用 `python -m http.server 8080` 也可以，但它不发缓存指令，Safari 会启发式缓存 js/css，
改完代码手机上可能一直是旧版本（"刷新也没用"多半就是这个原因）。

然后在电脑浏览器打开 <http://localhost:8080>。
在 `localhost` 下 Service Worker 可以正常注册，可完整测试离线功能。
（注意：通过局域网 IP + HTTP 访问时 Service Worker 不生效，走的是普通浏览器缓存。）

### 在 iPhone 上访问（同一 WiFi）

1. 查看电脑局域网 IP：`ipconfig`，找到 `192.168.x.x`
2. iPhone Safari 打开 `http://192.168.x.x:8080`
3. 分享按钮 → **添加到主屏幕**

> ⚠️ 通过 `http://192.168.x.x` 访问时 **Service Worker 不会生效**（浏览器要求 HTTPS 或 localhost）。
> 功能都正常，但离线缓存不可用，且启动时会闪一下地址栏。
> 想要完整的 PWA 体验（全屏、离线），请用下面的 GitHub Pages 方案。

## 部署到 iPhone（推荐：GitHub Pages，免费 HTTPS）

1. 在 GitHub 新建一个仓库（可设为 Private 或 Public）
2. 把 `novel-reader` 目录下的**所有文件**上传到仓库根目录
3. 进入仓库 **Settings → Pages**
   - Source 选择 `Deploy from a branch`
   - Branch 选择 `main`，目录选 `/ (root)`，保存
4. 等待 1-2 分钟，得到地址：
   `https://你的用户名.github.io/仓库名/`
5. 在 iPhone Safari 打开该地址
6. 分享按钮 → **添加到主屏幕**
7. 从主屏幕图标打开，即是全屏、无地址栏、可离线的 App

> 部署成功后，第一次打开需要联网加载以便缓存，之后断网也能正常阅读。

### 上传命令（如果你会用 git）

git commit -m "纯净阅读 v1.0"
git branch -M main
git remote add origin https://github.com/你的用户名/仓库名.git

## 使用说明

### 导入书籍
- 点书架右上角 **📥** → 选择文件（可多选）
- 或直接选 **📦 压缩包** 导入 ZIP，会自动解压出里面的小说
- 电脑端也支持把文件直接拖到页面上

### 书架操作
- **点击**书籍 → 打开阅读
- **长按**（或电脑右键）→ 收藏 / 移动到分类 / 删除

### 阅读中
- **点击屏幕中间** → 显示/隐藏顶部和底部栏
- **🔖 按钮** → 在当前位置添加书签
- **☰ 按钮** → 调整字号、行间距、主题
- **上一章 / 下一章** → 切换章节

### 管理书签
- 书架右上角 **🔖** → 查看所有书签 → 点击回到原书原位置

## 已知限制

| 限制 | 说明 |
|------|------|
| MOBI / AZW3 | 浏览器端无法解析 Kindle 格式。请先用 Calibre 转成 EPUB 或 TXT |
| PDF 重排版 | PDF 按页渲染，不能像 TXT 那样重排文字。适合阅读排版好的 PDF |
| 扫描版 PDF | 图片型 PDF 无法提取文字，只能原样显示，也无法全文搜索 |
| 存储上限 | iOS Safari 对单个网站存储通常限制在约 1GB。几百本 TXT/EPUB 没问题，大量 PDF 需留意 |
| 全文搜索 | 当前搜索针对**书名和作者**；正文全文搜索尚未实现 |
| 超大单章 | 单章超过 12 万字会自动切分为「（续N）」，避免排版卡死；单章最多渲染 6000 段并给出提示 |
| 加密 EPUB | 带 DRM 的 EPUB 无法解析（仅支持无 DRM 的正常 EPUB） |
| 备份 | 数据只在本机浏览器中。**清除 Safari 网站数据会丢失所有书籍**，重要书籍请保留原始文件 |
| 仿真翻页 | 是**整页刚性 3D 翻折 + 阴影扫过**，没有真实的纸页卷曲、纸张厚度和背面内容；也没有跟手拖拽（松手不接力） |
| 换章翻页 | 换章/切章时**不做**仿真动画（正文需异步重渲染），是瞬时切换 |
| PDF 与动画 | PDF 按页渲染，不参与多列分页；左右翻页在 PDF 下等于上/下一页 |
| 减少动效 | 暂未适配系统的 `prefers-reduced-motion`（如需关闭动画，请在阅读设置里手动选「无」） |
| 章内页码恢复 | **重开一本书时会回到该章第 1 页，而不是离开时那一页**（章节名是对的，页丢了）。属既有问题，2026-10 已确认仍未修 |
| 覆盖·跨章拖动 | 「覆盖」模式下**跨章**拖动时页面不跟手（相邻章尚未渲染、无法预铺），**松手才翻**，结果正确、阈值与其他模式一致；同章内跟手正常 |

项目自带 4 个测试脚本，无需安装任何依赖（只用 Node.js 内置模块）：

```powershell
cd novel-reader

node test-parser.js      # 核心解析逻辑（35 项）
node test-dom.js         # DOM 元素 ID / class 集成检查
node test-refs.js        # 跨文件函数引用检查
node test-globals.js     # 跨文件顶层变量/函数重名检查
node test-encoding.js    # UTF-8 / BOM 编码校验 + .bat 行尾检查

```

另外还有一个**浏览器端自检页**：用浏览器打开 `test-e2e.html`，
它会真实加载应用并运行完整断言（约 50 项），页面底部直接显示结果。
这是最快的自检方式——如果改动代码后想确认没改坏，打开这个页面即可。

> 这个页面还会验证**多列分页在真实浏览器布局下是否正常**（jsdom 测不了这一项）。

## 开发提示

- 所有 JS 都是**经典脚本**（非 ES Module），函数直接挂在全局，可以跨文件互相调用。
  加载顺序在 `index.html` 底部：`storage → parser → shelf → reader → app`。
  改动时不要用 `const`/`let` 声明跨文件共享的变量，否则不会挂到 `window` 上。
- `escapeHtml()` 定义在 `shelf.js`，被 `reader.js` 使用。
- 改了 `sw.js` 里的缓存资源列表后，记得同时把 `CACHE_NAME` 版本号 +1，
  否则用户浏览器会继续用旧缓存。
- 修改 `index.html` 里的 `id` 后，跑一下 `node test-dom.js` 可立刻发现断掉的引用。
- ⚠️ **不要在两个文件里用 `let`/`const` 声明同名变量。**
  这些都是经典脚本，共享同一个全局词法作用域；重名会让**后加载的文件整份解析失败**，
  症状是应用完全没反应、控制台报 `Identifier 'x' has already been declared`。
  改动后跑 `node test-globals.js` 可立刻发现。
- ⚠️ **`start-server.bat` 必须保持 CRLF 行尾**。cmd.exe 无法解析 LF-only 的批处理文件，
  症状是"双击后窗口一闪就关闭"。用编辑器改这个文件后如果出现该症状，
  跑 `node test-encoding.js` 会直接报出来。

| 切滚动残留动画类 | 切到上下滚动后 `anim-*` 类未移除（无视觉影响，但不变式不成立） |
| 冷启动残留动画类 | 滚动模式冷启动时 `anim-*` 仍被挂上 |
| 导入进度样式未生效 | `shelf.css` 用了不存在的 `#import-progress-text`（死选择器） |
| 书签小红点是死代码 | `.has-badge` 样式存在但从未被添加 |
| **大文件卡死** | 无章节标记的 txt 被整本当一章 → 生成 6 万个段落 → 手机排版长时间占满主线程，表现为「一直加载中、点什么都没反应」。已改为按字数自动分块（实测 2MB 文件：2.89s/6 万段 → **88ms/910 段**） |
| **底部按钮点不动** | `.tap-zones`（覆盖全页的翻页点击层，z-index:5）把底部栏盖住了，导致 上一章/目录/白天/阅读设置 全都点不到。已给底部栏加上更高的 z-index |
| **滑动翻页完全失效** | 滑动监听挂在 `#reader-content` 上，但真实触摸的落点是覆盖其上的 `.tap-zones`——它是前者的**兄弟节点**，事件不会冒泡过去，监听器一次都不会触发。已改挂到共同祖先 `#page-reader`，并加防重复守卫（一次轻扫只翻一页） |
| **翻页时上下栏会自动消失** | 用户的**明确需求**（不是缺陷）：翻页就说明在读正文，功能框应让开。已把「翻页 → 收起上下栏」作为正式行为实现（`turnPage()` 里调用 `hideReaderBars()`）。另外开书后既不翻页也不操作时仍会 3 秒自动收起；在上下栏上操作则不会 |
| **翻页动画卡顿** | 每次翻页都 `await saveCurrentProgress()`，一次 IndexedDB 事务（读取 + 结构化克隆 + 提交）全在主线程执行，**且恰好落在 0.28s 动画播放期间**。已改为**节流保存**（停下来后写一次，离开阅读器/切后台时 flush）。另外目录开着时每次翻页会重建整个章节列表（这本书 3013 章！），已改为只切换选中项的 class |
| 同文件函数重复定义 | `reader.js` 里 `swipeJustHandled()` 被定义两次，后者静默覆盖前者，导致按新实现写的逻辑不生效。已删除重复，并在 `test-globals.js` 增加**同文件重复定义**检查（该检查后来立刻抓到了新增 `readAsText` 时的同类错误） |
| **某些书打开是乱码** | 中文小说站的 txt 很多是 **GBK/GB18030** 编码，而之前一律用 `Blob.text()` 按 UTF-8 解码，非法字节全被替换成 `\uFFFD`。**已加入编码自动识别**：BOM → 严格 UTF-8 试解 → GB18030 → Big5（仅在 GB18030 明显不像中文时）→ 兜底。已用真实文件验证：16 MB 的 GBK 小说（3013 章）全书零乱码 |
| **改了代码手机却拿到旧版本** | HTTP 访问下 Service Worker 不生效，缓存完全由浏览器 HTTP 缓存决定；`python -m http.server` 不发任何缓存指令，Safari 就启发式缓存了 js/css —— 这是"刷新也没用"的根源。**已新增 `serve.py`**（对每个响应加 `no-store`，并输出正确的 MIME），`start-server.bat` 优先使用它 |
| **打开书本"点了没反应"** | `openBook()` 先 `await saveBook(book)`（把整本小说含文件重写一遍）才跳转；写入一慢或一失败（存储配额/事务中止），跳转就永远不发生，而点击处理器没接住异常 → 完全静默。已改为**先跳转、写入放后台且失败不影响打开** |
| 每翻一页写 4 遍整本书 | `saveCurrentProgress()` 调 4 次 `updateBookField`，而 IndexedDB 整条读写、书本记录里带着整个文件 → 每翻一页重写整本 4 遍。已合并为**一次**事务写入 |
| **连点导致浏览器放大** | `viewport` 里的 `user-scalable=no` **从 iOS 10 起被 Safari 忽略**，双击缩放依旧生效。已改用官方的 `touch-action: manipulation`（保留滚动、关掉双击缩放），翻页点击层用 `touch-action: none` 把手势完全交给 JS |
| **下拉触发浏览器刷新** | 滚动到顶后继续下拉，过卷被传递给文档。已把 `body` 固定（`position: fixed`）、`html/body` 设 `overscroll-behavior: none`，并给**所有可滚动容器**加 `overscroll-behavior: contain` |
| **第一次打开正常、之后打开任何书都失败** | 报 `NotFoundError: The object can not be found here.`。根因：文件本体内嵌在 `books` 记录里，而 IndexedDB 只能整条读写 —— 更新阅读进度（每翻一页、每次返回书架）都在重写整本书，刷新书架时 `getAll()` 还会把所有书的文件全量读进内存。WebKit 的 IndexedDB Blob 由临时文件支撑，这种模式下会在会话中途失效。**已把文件本体拆到独立的 `files` 表**：导入时写一次、之后永不重写；老数据自动迁移 |

> 说明：`验证者`的测试脚本位于工作区外的 `.e2e-env/` 目录，**不属于 App 交付物**，
> 不随本项目部署。

**两处未能自动化验证的地方**（均为测试环境限制，非代码问题）：

1. **ZIP 内文件的解压**（`entry.async`）在 jsdom 中不工作。
   已改为验证「真实 ZIP 结构解析」+「extractZip 自身的筛选逻辑」。
   JSZip 是浏览器通用成熟库，实际可用。
2. **多列分页的真实排版**依赖浏览器布局引擎，jsdom 不做布局。
   已通过伪造尺寸验证分页数学与翻页逻辑；CSS 多列的实际视觉效果需在浏览器中确认。
   另外 `fake-indexeddb` 不保留 Blob，因此"从数据库读回文件再解析"这一步未能自动化覆盖。

建议你首次使用时确认这两处：导入一个压缩包，以及翻页时看看每页是否正好一屏。
